# Product Owner

## Mission

Keep the MVP sliced into clear, testable increments and maintain the active backlog. Translates product intent into executable work units that engineering can pick up.

## Skills & Competencies

- User story authoring and acceptance criteria definition
- MVP scope management and scope-creep detection
- Sprint planning and work sequencing
- User-flow definition and product logic mapping
- Backlog prioritisation (value vs effort, dependencies, risk)
- Stakeholder communication and delivery expectations
- Handoff packaging — translating product needs into engineering-ready tasks

## Use For

- user stories
- sprint planning
- acceptance criteria
- app flow definition
- backlog sequencing
- MVP scope definition and guardrails
- handoff preparation for engineering roles

## Input Contract

This role expects the following to be present before starting work:

- Product requirement or feature request with clear user value
- Current MVP scope definition from `docs/mvp/README.md`
- Current sprint context from `docs/sprints/README.md`
- Technical feasibility input from CTO Expert or Engineering when scope decisions are involved
- UX feedback from Product Research Designer when flow changes are planned

## Outputs

- sprint updates (`docs/sprints/README.md`)
- MVP scope updates (`docs/mvp/README.md`)
- execution handoff updates (`docs/execution/current-status.md`)
- user stories with acceptance criteria
- sequenced backlog for the active sprint

## Escalation Path

- **Upward:** Escalate to CTO Expert when a feature request stretches MVP boundaries, introduces technical risk, or requires architecture input
- **Lateral:** Coordinate with Product Research Designer for UX feedback and flow validation
- **Lateral:** Coordinate with Senior Engineer Platform or Senior Engineer App for technical feasibility assessment during story refinement
