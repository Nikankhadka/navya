# Navya Docs

This folder holds the canonical product, architecture, design, execution, and standards documentation for Navya.

## Start Here

- `../README.md`: project overview, setup, commands, and onboarding
- `architecture/README.md`: system structure and technical boundaries
- `mvp/README.md`: canonical MVP scope and product rules
- `mvp/work-plan.md`: operational MVP delivery plan and weekly roadmap
- `execution/current-status.md`: current phase, blockers, and next recommended work
- `execution/qa-test-plan.md`: active QA plan for MVP/live Supabase validation
- `execution/weekly-issue-log.md`: weekly issues, severities, fix notes, and retest status
- `execution/decision-log.md`: operational product, QA, and delivery decisions
- `DESIGN_SYSTEM.md`: implemented design tokens and UI language
- `standards/frontend-standards.md`: frontend contribution rules

## Main Sections

- `architecture/`: system overview, domain boundaries, data model, auth, state, UI stack, AI flags, and release environments
- `adr/`: durable architecture decisions
- `design/`: route specs and visual direction
- `execution/`: handoff trail and current project state
- `mvp/`: product scope and MVP sequencing
- `onboarding/`: user-flow testing guidance
- `sprints/`: sprint-level delivery tracking
- `standards/`: implementation standards

## Documentation Ownership

Use `docs/mvp/README.md` as the source of truth for MVP scope. Use `docs/mvp/work-plan.md` for the current MVP delivery plan.

Use `docs/execution/current-status.md` as the source of truth for what is happening now. Keep active QA, issue, and operational decision records in `docs/execution/` so the project root stays focused on setup and entry points.
